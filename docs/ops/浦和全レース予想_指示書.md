# 指示書：南関東（浦和・大井・川崎・船橋）の全レース予想・信頼度別・結果照合

このまま Claude（Claude Code・このリポジトリ）に送れば、同じ作業を最初からやり直せるように書いてあります。
日付と競馬場は、使うたびに書き換えてください（以前の「浦和全レース予想」を4場に広げたもの）。

---

## プロンプト（ここから下を送る）

競馬分析ラボ（リポジトリ sukekyou0214/keiba-analysis-lab、作業ブランチ claude/keiba-lab-handover-5g9drw）で、
**<日付>（<曜日>）<競馬場>の全レース**の地方ベースの参考順位と、信頼度別を出してください。レースが終わったら、結果の照合もしてください。

### 守ること
- 予想はラボの計算だけで出す。AIが馬を選んだり、順位を手で直したりしない。
- 取得は本番アプリの共通ゲート（keiba_fetch_policy）だけを通す。直接の取得や、制限を回避することはしない。拒否されたら待つ。2回続けて拒否されたら止めて報告する。
- 生データや秘密情報は GitHub に置かない。置いてよいのは、レース前の順位の記録・検証ログ・照合結果だけ。
- 点数は確率として出さない（0〜100 はレース内の相対点）。「おすすめ」は根拠なしに書かない。
- 新しいモデルや区分は、計算する前に docs/accuracy/00-plan-and-preregistration.md へ判定の規則を書いてから使う。
- /tmp や Streamlit のメモリを、保存先として扱わない。レース前の記録は records/predictions/ に入れてコミットする。

### 手順
1. **取得（本番）**
   `NAR_DATE=<YYYYMMDD> NAR_KEY='場:<競馬場>' node scripts/ops/nar_prod.js start`
   - 状況は `... status` で確認する。「状態：完了」になったら `... zip <空のフォルダ>` で ZIP を取り、別の空のフォルダに展開する。
   - 当日に実行すると、まだ発走していないレースだけが対象になる。前日に実行すると全レースが対象になる。
2. **学習データを増やす**
   前日以前に取った同じ競馬場（や南関東の他場）のフォルダも、`--nar-work` に一緒に渡す。最初に書いたフォルダが予想の対象になる。
3. **計算**
   `python -I scripts/nar_local.py --nar-work <対象のフォルダ> <前日以前のフォルダ…> --out <出力> --date <YYYY-MM-DD> --version auto`
   - 主予測：`models/nar_v1.json`（浦和）または `models/nar_<競馬場>.json` が「採用」なら、それを使う。なければ nar-local-v1（v2・v3 は事前登録の規則で判定）。
   - 浦和では、`models/nar_v1s.json` があれば「nar-v1S順位」「nar-v1S点」も記録する（参考：南関東4場版、検証中。主予測にはしない）。
   - 使う方式が「近走人気だけ」を上回るかも確かめる。上回らなければ「根拠不足」と書く。
4. **信頼度別**
   ボックス向きの順（頭数の少ない順、同じなら上位5頭と6位以下の点差の大きい順）で、上位3レースを A、4〜6 を B、7 以下を C とする。
   地方の戦績が2走未満の馬が2頭以上いるレースは、1段下げる。
   過去の的中は `models/nar_tiers.json` から書く：確かめ済みの競馬場は「過去の<競馬場>（期間）での5頭ボックス的中：A ◯%…」、
   そうでなければ「この競馬場では未確認」（数字があっても「区分は未確認」と添える）。
5. **送る**
   `python -I scripts/nar_local_html.py --out <出力> --venue <競馬場> --date <YYYY-MM-DD>` で HTML を作り、CSV と一緒に送る。
   レース前に `records/predictions/<YYYYMMDD>_<競馬場>_local/` へ保存してコミット・プッシュする（PR → CI 通過 → スカッシュマージ → `git merge -s ours origin/main`）。
6. **レース後の照合**
   `NAR_DATE=<YYYYMMDD> NAR_KEY='結果' node scripts/ops/nar_prod.js start` → 完了したら zip を取り、照合する。
   - 照合は、レース前に保存した予想だけを使う。保存した時刻より前に発走したレースは対象外。
   - 出す数字：上位3頭に勝ち馬、予想1位の勝ちと3着以内、上位5頭ボックスの的中、実際の払戻での三連複（10点）と三連単（60点）の回収率、信頼度別の的中、参考として当日の人気上位5頭のボックス。浦和では nar-v1S の同じ数字も。
   - 結果は同じフォルダに追記してコミットする。競馬場ごとに累計し、100レースたまったら事前登録の規則で1回だけ見直す。

### 報告のしかた
- 先に結論を書く（何レース分を出したか、どの方式を使ったか、検証で通ったか）。
- 表は「信頼度・レース・発走・頭数・上位5頭」。
- 限界を必ず書く：馬場・オッズ・馬体重・取消は入っていない。信頼度が未確認の競馬場は、そのことを書く。

## 参考：これまでの結果
- 11/24 浦和（6R〜12R の7レース、v1）：上位3頭に勝ち馬 6/7、上位5頭ボックス 3/7、三連複の回収 63%、三連単の回収 47%。
- 浦和のレース単位の検証（9/1〜11/24、118レース）：C3U は近走人気だけを上回ったが下限 0.0 で不採用。信頼度は未確認（`docs/accuracy/14-nar-urawa.md`）。
- 南関東4場版 nar-v1S（`models/nar_v1s.json`）：11/26 以降の浦和で前向きに確かめ中（`docs/accuracy/15-nar-v1s-forward.md`）。
- 大井・川崎・船橋（9/1〜11/24、`docs/accuracy/16-nar-南関3場.md`）：大井は C2U を採用（`models/nar_大井.json`、近走人気だけ +6.5pt・下限 +1.1pt）。
  川崎・船橋は根拠不足で nar-local-v1 のまま。信頼度は大井・川崎が未確認、船橋は頭数だけの区分で確かめ済み（下限 +0.2pt、C1S の順位で確かめたもの）。
