## 1. 事前登録の追記（docs/accuracy/00、データを見る前）
- 候補名の混同を避ける：前の追記の候補 C1・C2 は「特徴量の組」の名前で、地方の格付けの C1 とは別物だと明記する。
- 追加する候補 C3：C2 に「地方の格付け」の3項目を足したもの。
- 格付けの点：Jpn1＝10、Jpn2＝9、Jpn3＝8、S1＝7、S2＝6、S3・地方重賞＝5.5、A1＝5、A2＝4.5、B1＝4、B2＝3.5、B3＝3、C1＝2.5、C2＝2、C3＝1.5。
- 「B2B3」「C1C2」のように2つにまたがる場合は平均。「C2三四」のような組分けは、無視して C2 とする。
- 2歳・3歳の限定戦、未格付、読めないものは「欠ける値」とし、学習期間の中央値で補う。
- 読み取る元：過去の走はレース名、対象のレースは一覧表記・レース名の括弧の中。
- 項目：地方格平均（直近5走の地方の走の格の平均）、格差（今回の格 − 地方格平均）、前走格。
- 限界として記録する：競馬場ごとの格の違い（大井の C1 と浦和の C1 は同じではない）は今回は補正しない。
- 組み合わせ：C1U・C2U・C3U・C1S・C2S・C3S（S は南関東4場を集められた場合だけ）。
- 選択の規則：前の追記と同じ（選択の期間 8/1〜8/31 の「上位3に勝ち馬」が最も高いもの。同率なら C1U→C2U→C3U→C1S→C2S→C3S の順）。
- 出走馬の戦績だけで作る今の方式（nar_local）：v3 として「v1＋格付けの3項目」を加える。判定は v2 と同じ規則（同じ検証の走で v3−v1 の AUC 差の95%区間の下限＞0 なら使う）。

## 2. コード
- keiba_nar_class.py（新規）：nar_class_level(text) で、格付けの文字列を上の点に直す。単体テスト（A1〜C3、B2B3、C2三四、Jpn2、(重賞)、2歳、読めない文字列）を書く。
- scripts/nar_backtest_test.py（新規）：dirt_test.py を元にする。
  - C1〜C3 と U/S の特徴量を作る。地方の4項目と格付けの3項目は、どれもその走より前の戦績だけから作る。
  - 選択の期間で1つ選び、最終の学習で作り直して、検証の期間で1回評価する。
  - 比べる相手：近走人気だけ、nar-local-v1（同じレースに当てはめる）、無作為。参考として当日の人気。
  - 出すもの：上位3勝ち馬、予想1位の3着内、三連複5頭ボックスの的中、信頼度区分別の的中、実際の払戻での回収率（三連複10点・三連単60点）。
- scripts/nar_local.py：--version auto で v2・v3 を、それぞれ規則どおり判定する（両方通れば、AUC の高いほうを使う。同じなら v2）。
- 既存のテストを全部通し、PR → CI → スカッシュマージ → git merge -s ours origin/main。

## 守ること（いつもどおり）
- 予想はラボの計算だけで出す。取得は共通ゲートだけを通し、拒否されたら待つ。生データは GitHub に置かない。
- 点数や的中率を、「当たる確率」として書かない。
- 止まったこと、うまくいかなかったこと、時間がかかったことは、そのまま報告する。
- 報告は結論から書く：使えるか、レース単位の的中率、信頼度別の的中率、回収率、どの候補を選んだか（格付けが効いたか）。
