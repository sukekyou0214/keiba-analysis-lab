## 2. 第2段階の事前登録（00、第2段階のデータを開く前）

### A. 浦和の予想を良くする（nar-v1S）
- 南関東4場の全レース（〜11/24）で学習する。特徴量の組は、第1段階で選んだ組に固定し、選び直さない。
- 確かめ方：浦和のこれからのレースだけで行う。2026-11-26 以降の開催日で、レース前に保存したものに限る。9/1〜11/24 の浦和は、第1段階で見たので使わない。
- 比べる相手：その時点の浦和の主予測、近走人気だけ、nar-local-v1。参考として当日の人気。
- 判定：レース前に保存した浦和のレースが 100レースたまったら、1回だけ行う。nar-v1S − 浦和の主予測（上位3に勝ち馬）の95%区間（2,000回、種0）の下限が0を上回れば、浦和の主予測を nar-v1S に替える。

### B. 大井・川崎・船橋のレースそのものの予想（競馬場ごと）
- 期間：選択の学習 〜7/31、選択 8/1〜8/31、最終の学習 〜8/31、検証 9/1〜11/24。検証は各競馬場で1回だけ見る。3場の検証期間は、まだ一度も見ていない。
- 候補：C1〜C3 × 学習データ（その競馬場だけ／南関東4場）。選択の規則は浦和と同じ（選択の期間の上位3勝ち馬が最も高いもの。同率なら「その競馬場だけ」→「南関東4場」、C1→C2→C3 の順）。
- 比べる相手：近走人気だけ、nar-local-v1、無作為。参考として当日の人気。
- 採用：選んだ方式 − 近走人気だけ の95%区間の下限が0を上回れば、その競馬場の主予測にする。上回らなければ nar-local-v1 のまま、「根拠不足」と明記する。
- 信頼度区分：浦和と同じ区分（A＝各日のボックス向き上位3、B＝4〜6、C＝7以下、地方の戦績2走未満が2頭以上で1段下げ）を、競馬場ごとに検証の期間で1回当てはめる。「A の5頭ボックス的中率 − 全レース」の下限が0を上回れば「その競馬場で確かめ済み」とする。
- 回収率：実際の払戻で、区分別の三連複5頭ボックス（10点）と三連単5頭ボックス（60点）の回収率を記録する。判断には使わない。
- 限界として記録する：競馬場ごとの格の違い（大井のC1と浦和のC1は同じではない）は補正しない。大井はナイター開催で、コースも大きく違う。

## 3. コード
- keiba_backtest：複数の競馬場（BT_VENUE=大井,川崎,船橋）を1回の作業で集められることを確かめる。作業名は競馬場ごとに分けてもよい。
- scripts/nar_backtest_test.py：
  - --venue（予想の対象にする競馬場）を足し、B を競馬場ごとに回せるようにする。
  - --stage fit-only を足す。学習だけを行い、モデルを models/nar_v1s.json（A）や models/nar_<競馬場>.json（B）に保存する。
- scripts/nar_local.py：
  - 競馬場ごとに、採用されたモデルがあればそれを使い、なければ nar-local-v1 を使う。
  - 浦和では、主予測とは別に nar-v1S の順位と点も計算し、レース前の記録に「nar-v1S順位」「nar-v1S点」の列として保存する。
- 予想の取得：NAR_KEY='場:川崎' などで、浦和と同じように当日の全レースを取る。
- 結果照合：競馬場ごとに、主予測（浦和では nar-v1S も）の上位3勝ち馬・予想1位の3着内・5頭ボックスの的中・区分別の的中・回収率を出す。
- 既存のテストを全部通し、PR → CI → スカッシュマージ → git merge -s ours origin/main。

## 守ること（いつもどおり）
- 予想はラボの計算だけで出す。取得は共通ゲートだけを通し、拒否されたら待つ。2回続けて拒否されたら止めて報告する。
- 生データは GitHub に置かない。点数や的中率を、「当たる確率」として書かない。
- 止まったこと、うまくいかなかったこと、時間がかかったことは、そのまま報告する。
- 報告は結論から書く：使えるか、レース単位の的中率、信頼度別の的中率、回収率、どの候補を選んだか（格付けが効いたか、南関東4場で学ばせたのが効いたか）。
